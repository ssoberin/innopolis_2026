# Критерии оценки хакатона

Максимальная оценка — **100 баллов**.

| Критерий | Максимальный балл | Способ оценки |
| --- | ---: | --- |
| Определение целевых микрокатегорий | 60 | Автоматически, по micro-F1 |
| Работоспособность и проработка решения | 25 | Экспертная оценка на live-демо и защите |
| Качество сгенерированных черновиков | 15 | Экспертная оценка на live-демо |

Генерация текстов — дополнительная часть задачи. Решение без неё может получить баллы за классификацию и проработку, но не получает баллы за качество черновиков.

## 1 Определение целевых микрокатегорий

**До 60 баллов**

Для каждого объявления решение возвращает набор целевых микрокатегорий — значения `mcId` из списка `drafts`.

Эталон содержит микрокатегории, для которых следует создать дополнительные объявления. Исходная микрокатегория в эталонный набор не включается. Если дополнительные черновики не нужны, эталонный набор пуст.

Для объявления $i$ считаются:

- $TP_i$ — число предсказанных микрокатегорий, которые есть в эталоне;
- $FP_i$ — число предсказанных микрокатегорий, которых нет в эталоне;
- $FN_i$ — число микрокатегорий из эталона, которые решение пропустило.

Счётчики суммируются по всем $N$ объявлениям проверочного набора:

$$
\mathrm{micro\text{-}F1} =
\frac{2\sum_{i=1}^{N} TP_i}
{2\sum_{i=1}^{N} TP_i + \sum_{i=1}^{N} FP_i + \sum_{i=1}^{N} FN_i}
$$

Например, если эталонный набор — `{102, 104}`, а решение вернуло `{102, 105}`, результат для объявления: один `TP`, один `FP` и один `FN`.

**Баллы за классификацию = 60 × micro-F1.**

Во второй день соревнований участникам будет предоставлен проверочный набор данных. Оценка классификации по micro-F1 будет проводиться по результатам работы решений на этом наборе.

Повтор одного `mcId` не увеличивает число правильных ответов.

Для расчёта метрики используйте готовую реализацию [sklearn.metrics.f1_score](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.f1_score.html) с параметром `average="micro"`. Эталон и предсказания нужно представить как бинарные матрицы: строки соответствуют объявлениям, столбцы — микрокатегориям в одинаковом порядке, 1 означает наличие микрокатегории в наборе, 0 — отсутствие.

## 2 Работоспособность и проработка решения

**До 25 баллов**

Жюри оценивает решение по live-демо и ответам команды: работает ли полный сценарий обработки нового объявления, обоснован ли технический подход, учтены ли ошибки, уязвимости и ограничения. Команда должна объяснить устройство решения и возможность его повторного запуска.

При сопоставимом качестве преимущество получают более быстрые и экономичные решения. Приветствуются открытые модели, самостоятельное развёртывание и оптимизация обращений к LLM. Платные API допускаются.

Команда указывает используемые модели, время и стоимость обработки для итоговой конфигурации, отделяя измеренные показатели от приблизительных оценок.

За блок выставляется общая оценка до 25 баллов. Сложность архитектуры и оформление презентации сами по себе дополнительных баллов не дают.

## 3 Качество сгенерированных черновиков

**До 15 баллов**

На live-демо жюри оценивает пары «исходное объявление — черновик» для выбранных организаторами микрокатегорий. Примеры одинаковы для всех команд. Исходник и результат показываются рядом, без ручной правки.

**Хороший черновик:**

- посвящён целевой микрокатегории и понятен как отдельное объявление;
- сохраняет полезные детали исходника без выдуманных услуг, цен и обещаний;
- написан грамотно и структурированно, без воды, повторов и потери важных сведений.

**Плохой черновик:** копирует исходное объявление без адаптации, содержит нерелевантные услуги или выдуманные условия, теряет полезные детали либо выглядит как неинформативный шаблон.

Подходящие формулировки исходника можно сохранять: процент совпадения и перефразирование ради уникальности не оцениваются.

Жюри выставляет общую оценку до 15 баллов, без разбивки по отдельным аспектам.

## Защита и live-демо

На защите команда должна:

- показать работу решения на примерах организаторов в реальном времени: от входного объявления до целевых микрокатегорий и черновиков, если генерация реализована;
- объяснить подход и назвать используемые модели;
- представить показатели скорости и стоимости, разобрать ошибки, уязвимости и ограничения решения.

Скриншоты и запись могут дополнять защиту, но не заменяют live-демо.

## Итоговый результат

Итоговый балл — сумма трёх оценок. При равенстве баллов выше ставится команда с большим micro-F1 на проверочном наборе; при дальнейшем равенстве — с более высокой оценкой работоспособности и проработки решения.
